# Sprint 1 Prototype

## Feature: การจัดการข้อมูลการเงิน

### User Story ที่อ้างอิง

**US-04: บันทึกรายรับ**

As a ผู้ใช้งาน  
I want บันทึกข้อมูลรายรับ  
So that สามารถติดตามเงินที่ได้รับได้

**US-05: บันทึกรายจ่าย**

As a ผู้ใช้งาน  
I want บันทึกข้อมูลรายจ่าย  
So that สามารถติดตามค่าใช้จ่ายของตนเองได้

**US-06: ดูสรุปรายรับและรายจ่าย**

As a ผู้ใช้งาน  
I want ดูยอดรวมรายรับและรายจ่าย  
So that สามารถเห็นภาพรวมทางการเงินของตนเองได้

## Tracer vs Prototype

**ประเภท:** Prototype

Prototype นี้สร้างขึ้นเพื่อแสดงแนวทางการใช้งานและหน้าตาของฟีเจอร์การจัดการข้อมูลการเงิน โดยเน้นการทดลอง User Flow และการแสดงผลของหน้าจอ

Prototype ไม่ใช่ระบบจริง และไม่ได้เชื่อมต่อกับ Backend หรือ Database จริง

## สิ่งที่ทำได้

1. ผู้ใช้สามารถกรอกข้อมูลรายรับและรายจ่ายผ่านแบบฟอร์มได้
2. ผู้ใช้สามารถดูรายการรายรับและรายจ่ายที่แสดงบนหน้าจอได้
3. ระบบแสดงยอดรวมรายรับ รายจ่าย และยอดคงเหลือในรูปแบบสรุป

## สิ่งที่ไม่ได้ทำ (Deliberately)

1. ยังไม่ได้เชื่อมต่อกับ Backend หรือ Database จริง
2. ยังไม่ได้ทำระบบ Authentication และ Security จริง
3. ยังไม่ได้รองรับข้อมูลจำนวนมากหรือการใช้งานพร้อมกันหลายคน
4. ยังไม่ได้ทำ Responsive Design สำหรับทุกขนาดหน้าจอ
5. ยังไม่ได้ทำระบบตรวจสอบข้อมูลฝั่ง Server
6. ข้อมูลใน Prototype เป็นข้อมูลตัวอย่างและอาจหายเมื่อรีเฟรชหน้า

## Next Step: Sprint 2

ใน Sprint 2 จะนำ Prototype ไปพัฒนาต่อเป็นระบบที่สามารถใช้งานได้จริง โดยจะดำเนินการดังนี้

1. เชื่อมต่อ Frontend กับ Backend API
2. เชื่อมต่อ Database สำหรับจัดเก็บข้อมูลรายรับและรายจ่าย
3. เพิ่มระบบ Authentication และการจัดการ Session
4. เพิ่ม Validation สำหรับข้อมูลที่ผู้ใช้กรอก
5. ปรับปรุง Dashboard ให้แสดงข้อมูลจาก Database จริง
6. ทดสอบการทำงานของฟีเจอร์ด้วยข้อมูลจริง
