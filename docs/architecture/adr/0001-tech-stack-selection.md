# ADR-001: Selection of Core Technology Stack

**Status:** Accepted

**Context:**
โครงการของพวกเรามีชื่อว่า DaybyDay เป็นเว็บแอปพลิเคชันสำหรับการรวบรวมและจัดการข้อมูลส่วนบุคคล (เช่น การเงิน สุขภาพ และตารางกิจกรรม) สำหรับผู้ใช้งานทั่วไป พวกเราเป็นทีมงานนักศึกษาจำนวน 4 คน ได้แก่:

นายธนภัทร เอี่ยมสอาด
นายอริญชัย ปิ่นทอง
นางสาวสลิลทิพย์ ดอกนางแย้ม
นายคชภัค เสนาน้อย

พวกเรามีความคุ้นเคยและมีประสบการณ์เดิมในเทคโนโลยีเว็บเบส ข้อจำกัดหลักของพวกเราคือกรอบระยะเวลาการดำเนินงาน และความจำเป็นในการสร้างแบบจำลองเพื่อทดสอบอย่างรวดเร็ว รวมถึงการปรับปรุงแก้ไขซ้ำ

**Decision:**
พวกเราตัดสินใจเลือกใช้สแต็กเทคโนโลยีหลัก (Core Technology Stack) :
- **Frontend:** React พร้อมกับ Vite และ TypeScript
- **Backend:** Python พร้อมกับ Flask (หรือ NestJS / Node.js)
- **Database:** PostgreSQL พร้อมด้วย Prisma ORM
- **Deployment:** Vercel สำหรับ Frontend และ Render / Supabase สำหรับ Backend & Database

**Consequences:**
*   **Positive:**
    - สแต็กเทคโนโลยีที่เลือกสอดคล้องกับทักษะและความถนัดเดิมของสมาชิกในทีม ช่วยลดระยะเวลาในการเรียนรู้ (Learning Curve) และเร่งความเร็วในการพัฒนาช่วงเริ่มต้นได้เป็นอย่างดี
    - โครงสร้างเชิงคอมโพเนนต์ (Component Model) ของ React และ TypeScript ช่วยให้สามารถนำองค์ประกอบ UI กลับมาใช้ซ้ำได้ง่าย ลดความผิดพลาดของโค้ด และทำให้ระบบคงทนขึ้น
    - โครงสร้างแบบเชิงสัมพันธ์ (Relational Structure) ของ PostgreSQL เหมาะสมอย่างยิ่งกับการจัดการความสัมพันธ์ของข้อมูลที่ซับซ้อน เช่น ข้อมูลโปรไฟล์ผู้ใช้ รายการการเงิน และเป้าหมายสุขภาพ
*   **Negative:**
    - การไม่ได้เลือกใช้ Full-stack Framework (เช่น Next.js) ทำให้ทีมต้องบริหารจัดการ Deployment และการเชื่อมต่อ API ระหว่าง Frontend และ Backend แยกออกจากกัน
    - การเลือกใช้บริการ Cloud แบบ Free Tier (เช่น Render หรือ Vercel) อาจเจอปัญหาความล่าช้าจากการเริ่มระบบใหม่เมื่อไม่มีการใช้งานระยะหนึ่ง (Cold Starts) ซึ่งต้องระมัดระวังเป็นพิเศษในระหว่างการนำเสนอผลงาน (Demo)
